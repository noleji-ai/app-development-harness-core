# Maintain a reproducible public development baseline

The first goal is source another developer can inspect, initialize and test. Subsequent work should respond to reproduced failures and actual needs. Public history starts here; local preparation does not establish continuous public releases.

## Current priorities

Check additional environments, collect compatibility and recovery cases, improve bilingual instructions and compare existing alternatives. Keep failures and unresolved limits alongside successes. Independent reuse and live-provider behavior remain unverified.

## Record changes and results

Link meaningful changes to the issue or reproduction, version, relevant check command, result and remaining work. Distinguish fixtures, maintainer use and independent users. Record API usage only when a model is called; local test counts do not demonstrate token savings.

## Review the public boundary

Review contributions and notices before merging. Share synthetic inputs rather than customer/student data. Follow the security instructions for sensitive issues. This plan guarantees no support response time, release schedule, grant funding or unattended background work.
