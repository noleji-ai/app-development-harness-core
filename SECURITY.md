# Reporting a security problem

Execution boundaries, path handling, decision records, and artifact validation can affect the files a coding agent is allowed to change. Please report suspected problems without including real credentials or customer data.

## Share sensitive details privately

Use GitHub's “Report a vulnerability” option if it is enabled for this repository. If that option is unavailable, open an issue asking the maintainer for a private reporting channel. Do not include exploit details or sensitive files in the public issue. Private reporting availability must be checked on the published repository; this file does not enable it.

## Include a minimal reproduction

Provide the affected source revision, operating system and tool versions, expected boundary, observed behavior, and a small synthetic reproduction. State which files or permissions could be affected. Keep the reproduction confined to systems you own or are authorized to test.

## Current support limits

Version 1.2.0 is the source baseline prepared for public review. Security response is best effort, with no guaranteed response time or formal long-term support policy. Passing local checks is not a security certification. Codex Security access has not been granted through an OpenAI support program.
